## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage                                                        |
| ----- | ----- | ------------------------------------------------------------ |
| xs    | 4px   | Icon gaps, inline padding, tight row hint offsets            |
| sm    | 8px   | Compact control spacing, icon-button hit-area interior       |
| md    | 16px  | Default row padding, default element spacing                 |
| lg    | 24px  | Section spacing and grouped-control separation               |
| xl    | 32px  | Layout gaps inside wide panes                                |
| 2xl   | 48px  | Major section breaks where existing layouts already use them |
| 3xl   | 64px  | Page-level spacing where existing layouts already use them   |

Exceptions: existing theme also defines `6px`, `12px`, `80px`, `96px`, and `128px`; Phase 03 must not introduce new spacing values. Icon-only controls keep existing app hit targets and should remain at least 32px visually on desktop and usable through existing native touch hit slop/sheet controls on compact native.

Phase-specific spacing:

| Element                | Contract                                                                                                                                              |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Provider rows          | Keep existing settings/provider row padding: `theme.spacing[4]` horizontal and vertical in settings cards.                                            |
| Model rows             | Keep existing `CombinedModelSelector` desktop row height around 40px; context variants must not increase row height.                                  |
| Composer control chips | Keep existing compact chip dimensions and gaps; longer labels truncate with `numberOfLines={1}` instead of resizing controls.                         |
| Provider icon          | Use existing provider icon sizes: `theme.iconSize.sm` in list/model rows, `theme.iconSize.md` in chips, `theme.iconSize.lg` in compact model trigger. |

## Typography

| Role    | Size | Weight | Line Height |
| ------- | ---- | ------ | ----------- |
| Body    | 16px | normal | 1.5         |
| Label   | 12px | normal | 1.5         |
| Heading | 16px | 500    | 1.2         |
| Display | 20px | 500    | 1.2         |

Use only these four size roles for new Phase 03 UI text. Existing components may keep their internal token usage (`fontSize.xs`, `fontSize.base`, etc.). Do not add oversized headings, marketing copy, badges, or card-heavy layout.

Typography rules:

| Text                     | Contract                                                                                                                                                            |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Provider row title       | `Cursor SDK`, `fontSize.base`, normal weight, foreground.                                                                                                           |
| Provider row description | Muted, `fontSize.xs`, normal weight.                                                                                                                                |
| Mode labels              | Exactly `Sandbox` and `YOLO`; existing mode formatter may sentence-case raw ids only when no label exists.                                                          |
| Model/context labels     | Base display name plus context with a spaced hyphen: `GPT-5.5 - 1M`. No bare base row when context variants exist.                                                  |
| Boolean thinking labels  | Exactly `Thinking On` and `Thinking Off`.                                                                                                                           |
| Feature label/tooltip    | Use existing feature control copy with a Cursor SDK-specific `Fast` label only if a visible label is needed; tooltip: `Use Cursor SDK fast mode for the next turn`. |

## Color

| Role            | Value                                                                                         | Usage                                                                                     |
| --------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Dominant (60%)  | `theme.colors.surface0` / light `#ffffff`                                                     | App background, workspace panes, sheet backgrounds                                        |
| Secondary (30%) | `theme.colors.surface1` / light `#fafafa` and `theme.colors.surfaceSidebar` / light `#f4f4f5` | Settings cards, provider rows, sidebar/list surfaces, selector rows                       |
| Accent (10%)    | `theme.colors.accent` / light `#20744A`                                                       | One primary action in a region, retry/refresh only where existing UI uses primary buttons |
| Destructive     | `theme.colors.destructive` / light `#b04138`                                                  | Destructive confirmations only                                                            |

Accent reserved for: primary `Button variant="default"` in existing retry/refresh contexts, selected/focused states already owned by existing controls, and no new Cursor SDK-specific highlighting. Do not use accent for the experimental state, Cursor SDK label, provider icon tint, or YOLO warning.

Semantic color contract:

| Semantic            | Contract                                                                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| YOLO/dangerous mode | Use existing `dangerous` mode visual tier (`ShieldOff`, dangerous tier). Do not add a red badge.                                     |
| Sandbox/safe mode   | Use existing `safe` mode visual tier (`ShieldCheck`, safe tier) only when the dynamic snapshot exposes Sandbox.                      |
| Unavailable/error   | Use existing selector error state and diagnostic sheet copy. Inline error text remains scoped and muted/red per existing components. |
| Disabled            | Use opacity only (`theme.opacity[50]`); do not change colors for disabled provider/mode/model rows.                                  |

| Surface                             | Copy / Behavior                                                                                                                                                               |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| Provider id                         | `cursor-sdk`; never display this id as the normal label.                                                                                                                      |

| Existing Cursor ACP label           | Keep existing `Cursor` label and description. Do not rename to `Cursor ACP` in Phase 03.                                                                                      |
| Mode labels                         | `Sandbox`, `YOLO`. Do not display `Agent`, `Ask`, `Default`, or `Allow All` for Cursor SDK.                                                                                   |
| Current runtime mode availability   | Creation and composer controls show only `YOLO` while Sandbox is unsupported.                                                                                                 |
| Sandbox unsupported diagnostics     | `Sandbox is not supported in this Cursor SDK runtime. YOLO is the only available mode.` This belongs in diagnostics/settings, not in the mode picker.                         |

| Model loading                       | Reuse existing `Loading...` selector state.                                                                                                                                   |
| Model discovery failure             | Use existing selector error/retry path with the error copy above.                                                                                                             |
| Successful empty SDK list           | Treat as unavailable/error; do not show `Default`.                                                                                                                            |
| Thinking selector unset             | Do not synthesize or show a selected thinking value until the user chooses one. If a placeholder is needed, use existing `Thinking` title/trigger conventions, not `Default`. |
| Boolean thinking options            | Display `Thinking On` and `Thinking Off`; send SDK raw `true` and `false`.                                                                                                    |
| Running-agent parameter changes     | No toast or modal on successful changes. Existing controls update selection; change applies on the next user turn.                                                            |
| In-flight turn                      | Do not interrupt, restart, or show interruption copy when model/context/reasoning/fast changes while a turn is running.                                                       |

Voice and punctuation: sentence case, no trailing periods for labels/buttons/single-clause hints, direct error copy, no apology language.

## Phase Interaction Contract

### Provider Identity and Side-by-Side Behavior

| Requirement             | Contract                                                                                                                                                                                                |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Side-by-side providers  | Provider lists may show both `Cursor` and `Cursor SDK` as separate rows when both are enabled. They must not be merged, grouped, or renamed.                                                            |
| Cursor ACP preservation | Existing `cursor` ACP catalog/provider behavior, icon, modes, model discovery, and config semantics are unchanged.                                                                                      |
| Cursor SDK availability | If unavailable due to missing `CURSOR_API_KEY`, failed SDK model discovery, or empty SDK model list, `Cursor SDK` remains visible in settings/diagnostics but is not selectable for new agent creation. |
| Creation picker         | Selectable provider/model rows include `Cursor SDK` only when its snapshot status is `ready` and it has at least one model row.                                                                         |
| Diagnostics/settings    | Unavailable Cursor SDK row must expose the existing diagnostics path with the provider description and concrete reason.                                                                                 |

### Icon Contract

| Case              | Contract                                                                                                                                                                                                             |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cursor-sdk` icon | Resolve to the existing Cursor brand icon used by the `cursor` catalog entry.                                                                                                                                        |
| Fallback          | `cursor-sdk` must never fall back to lucide `Bot` in provider rows, model rows, compact trigger, or running-agent controls.                                                                                          |
| Tint              | Use existing icon tint behavior (`foregroundMuted` in rows/chips, selected color where existing primitive applies). Do not introduce brand-color fills unless the existing Cursor catalog SVG already contains them. |
| Tests             | Include a focused icon resolver test proving `cursor-sdk` resolves to Cursor, not `Bot`.                                                                                                                             |

### Mode Contract

| State                                | Creation/composer controls                                                                       | Diagnostics/settings                                                    |
| ------------------------------------ | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| Current runtime: Sandbox unsupported | Show exactly one mode option: `YOLO`. It is the effective default because it is the only option. | Show the Sandbox unsupported reason if diagnostics expose mode details. |
| Future runtime: Sandbox supported    | Show `Sandbox` and `YOLO`. Default to `Sandbox`.                                                 | No unsupported warning.                                                 |
| Static manifest                      | May define both `Sandbox` and `YOLO` labels/descriptions/visuals.                                | Must not force Sandbox into controls when dynamic snapshot omits it.    |

Mode visuals:

| Mode    | Icon          | Tier        | Notes                                           |
| ------- | ------------- | ----------- | ----------------------------------------------- |
| Sandbox | `ShieldCheck` | `safe`      | Only visible when dynamic snapshot includes it. |
| YOLO    | `ShieldOff`   | `dangerous` | Mark as unattended in metadata. No extra badge. |

### Model Selector Contract

| SDK metadata shape                       | UI rows                                                                                          |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Model has no context parameter           | One row: SDK display name, e.g. `Auto`.                                                          |
| Model has context values                 | One row per context value, e.g. `GPT-5.5 - 272K`, `GPT-5.5 - 1M`.                                |
| Model has context values                 | Do not show a bare `GPT-5.5` base row.                                                           |
| SDK model list succeeds with zero models | Provider becomes unavailable/error; do not show synthetic `Default`.                             |
| SDK model discovery fails                | Provider becomes unavailable/error with retry; provider-config models must not mask the failure. |

Ordering: preserve SDK model order, then SDK context value order. Do not mark an SDK default context as preferred. All model/context combinations are peers.

Model row anatomy:

| Element       | Contract                                                                                                                           |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Label         | SDK `displayName` plus context suffix when present.                                                                                |
| Description   | Existing model description slot may show SDK description or raw id; do not overload it with experimental status.                   |
| Favorite star | Existing favorite behavior remains available where the selector already supports it.                                               |
| Search        | Existing `CombinedModelSelector` search must match base label, context label, raw SDK model id, provider label, and description.   |
| Stable id     | Internal row id must be stable and reversible to SDK `ModelSelection`: `{ id: string, params?: [{ id: string, value: string }] }`. |

### Thinking and Reasoning Contract

| Requirement               | Contract                                                                                                                                                               |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Source                    | SDK `reasoning`, `effort`, and boolean `thinking` metadata map to existing `thinkingOptions` only for models exposing those parameters.                                |
| No implicit default       | Do not auto-select SDK default thinking/reasoning values and do not fall back to the first thinking option for `cursor-sdk`. Blank remains blank until user selection. |
| Boolean labels            | Boolean `thinking` values display as `Thinking On` / `Thinking Off`, while sending raw SDK values `true` / `false`.                                                    |
| Raw values                | Preserve SDK raw parameter ids and values per model. Do not normalize `xhigh`, `extra-high`, `max`, boolean strings, or effort labels across providers.                |
| Invalid selection cleanup | If refreshed metadata removes the selected thinking/reasoning value, clear it. Do not silently select an SDK default.                                                  |
| Running agent             | A selected thinking/reasoning option applies on the next turn through SDK per-send params.                                                                             |

UI display:

| Surface         | Contract                                                                                                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Draft desktop   | Show thinking chip only when the selected Cursor SDK model exposes options and a user has a valid selection or the control is needed to choose one. Do not prefill the first option. |
| Draft compact   | Use existing icon button + compact sheet. Sheet title remains `Thinking`; option labels follow this contract.                                                                        |
| Running desktop | Show the thinking chip only when options exist. If unset, show neutral `Thinking` trigger or no selected value; do not display the first option as selected.                         |
| Running compact | Existing `Brain` icon opens the thinking sheet when options exist.                                                                                                                   |

### Fast Toggle Contract

| Requirement     | Contract                                                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Source          | SDK `fast` parameter maps to existing `AgentFeature` toggle only when the selected model exposes `fast`.                             |
| Default         | Always off/false in Paseo, even if SDK metadata marks a fast variant as default.                                                     |
| Placement       | Use existing feature controls: desktop icon control in the composer control row; compact `Features` sheet.                           |
| Icon/color      | Existing `fast_mode` mapping: `Zap` icon and yellow highlight only when enabled.                                                     |
| Copy            | Label `Fast`; tooltip `Use Cursor SDK fast mode for the next turn`. Compact feature sheet uses the existing feature row/toggle copy. |
| Invalid cleanup | If model changes or refreshed metadata removes `fast`, clear `fast_mode` from draft/running feature values and preferences.          |

### Responsive Contract

| Environment          | Contract                                                                                                                                                                                                      |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Compact native       | Model/provider selection uses existing compact `CombinedModelSelector` sheet. Thinking opens as a compact sheet. Features open in `AdaptiveModalSheet`. Hover-only affordances must be visible without hover. |
| Desktop web          | Provider/model/thinking/mode controls use anchored `Combobox`/tooltip behavior. No layout shift when long model/context labels render.                                                                        |
| Electron             | Same web layout behavior as browser unless existing Electron platform files already specialize the surface. Do not add Electron-only UI for this phase.                                                       |
| Settings list/detail | Keep canonical compact stack and desktop sidebar+detail behavior; do not add a new page shape.                                                                                                                |

Text fitting: long labels such as `Gemini 3.5 Flash` and `GPT-5.5 - 272K` must fit without overlapping adjacent controls. Compact trigger may shorten namespace-style labels through existing `shortModelLabel`, but must preserve context suffixes.

### Accessibility and Interaction States

| State           | Contract                                                                                                                                                                                                              |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Loading         | Use existing inline selector loading state (`Loading...`) and small spinners where existing components already use them.                                                                                              |
| Error           | Use existing selector error rows and diagnostics sheet retry path. Error scope stays provider/model-specific.                                                                                                         |
| Retry           | Retry refreshes the provider snapshot/model metadata through existing refresh APIs. Button copy: `Retry`; pending copy: `Retrying...` where supported.                                                                |
| Disabled        | Disabled controls remain visible when useful for context and use opacity only.                                                                                                                                        |
| Hover           | Do not introduce new hover reveal patterns. If a row action is hover-revealed, follow `docs/hover.md`: hover state on plain `View`, press on inner `Pressable`, native/compact controls always visible.               |
| Touch           | No control required for selecting provider/model/mode/thinking/fast may be hover-only on native or compact layouts.                                                                                                   |
| Keyboard/search | Existing combobox search behavior remains; no custom keyboard shortcuts in Phase 03.                                                                                                                                  |
| Announcements   | Buttons keep `accessibilityRole="button"` and labels such as `Select agent mode (YOLO)` / `Select thinking option`. For boolean feature toggles, expose selected state if the existing feature primitive supports it. |

## Acceptance Criteria

- `Cursor SDK` appears as a built-in provider label with description `Requires CURSOR_API_KEY. Experimental direct Cursor SDK provider for local agents.`
- Existing `Cursor` ACP provider label, icon, modes, catalog behavior, and config behavior are unchanged.
- `cursor-sdk` resolves to the Cursor brand icon in provider rows, model rows, compact model trigger, and running-agent controls; it never shows the generic `Bot` fallback.
- With current unsupported Sandbox runtime, creation and composer mode controls show only `YOLO`; diagnostics/settings may show the Sandbox unsupported reason.
- With injected/proven Sandbox support, controls show `Sandbox` and `YOLO`, with `Sandbox` as default.
- Cursor SDK never shows `Agent`, `Ask`, or synthetic `Default` as v1 modes/model rows.
- SDK models with context values render only explicit context variants, using labels such as `GPT-5.5 - 1M`; no bare base row is shown for those models.
- SDK model discovery failure or a successful empty SDK model list makes Cursor SDK unavailable for creation and shows existing retry/diagnostic behavior.
- Boolean thinking options render as `Thinking On` / `Thinking Off` and send raw SDK values `true` / `false`.
- Cursor SDK thinking/reasoning controls do not auto-select SDK defaults or first options; unset remains unset until the user chooses.
- `fast` appears only for selected Cursor SDK models that expose it, defaults off, uses existing feature-toggle UI, and clears when no longer valid.
- Running-agent model/context/reasoning/fast changes update controls and apply on the next turn without interrupting an in-flight turn.
- Compact native, desktop web, and Electron all use existing controls with no overlapping text, no new card-heavy layouts, and no hover-only required actions.
