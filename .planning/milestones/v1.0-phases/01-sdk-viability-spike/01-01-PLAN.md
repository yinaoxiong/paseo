# Plan 01-01: Run and Document SDK Local Lifecycle Experiments

<objective>
Create a bounded, phase-local spike harness proving whether `@cursor/sdk` can run as a local direct-provider dependency in Paseo's server workspace. This plan may add dependency and spike artifacts only; it must not create a production `cursor-sdk` provider or edit registry/manifest production files.
</objective>

<threat_model>

- **High: credential leakage.** Result JSON, logs, stdout summaries, scripts, and Markdown must record only `hasCursorApiKey`; never record the key value. Block if any artifact contains a raw `CURSOR_API_KEY` value or obvious `sk-` secret token.
- **High: unsafe local execution.** Every real `Agent.create` call must use a disposable minimal git repo as `local.cwd`, never `/mnt/private_yax_qy4/projects/paseo`. Block if the recorded SDK cwd is the Paseo checkout or cannot be proven.
- **High: destructive YOLO behavior.** YOLO prompts must be harmless and confined to scratch repo files. Block if a prompt requests deletes, host scans, network exfiltration, daemon control, or non-scratch writes.
- **Medium: SDK stores contain sensitive material.** Use minimal fixture prompts, keep stores under the phase directory or the documented provider-scoped store path, and redact previews.
- **Medium: dependency validation outside devcontainer.** Dependency install, format, typecheck, lint, and build/test verification must run inside `/workspaces/paseo` in the devcontainer.

High severity threats block execution until fixed or recorded as a redacted stop finding.

</threat_model>
