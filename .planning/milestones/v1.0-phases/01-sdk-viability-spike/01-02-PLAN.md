# Plan 01-02: Design Provider State, Persistence, Error Mapping, and Mode Mapping

<objective>
Write the human-readable spike conclusion and Phase 2 provider design guidance from 01-01 evidence. This plan must not implement production provider code and must not edit `provider-registry.ts`, `provider-manifest.ts`, or a future production provider file.
</objective>

<threat_model>

- **High: secret disclosure in conclusion docs.** `01-SPIKE-RESULTS.md` must summarize key presence and redacted errors only. Block if it includes a raw `CURSOR_API_KEY`, `sk-` token, or raw log section containing credentials.
- **High: unsafe SDK local execution evidence.** `01-SPIKE-RESULTS.md` must not recommend `Proceed` from live SDK results unless the result JSON proves SDK `cwd` was a scratch git repo and not `/mnt/private_yax_qy4/projects/paseo`. Block or recommend `Adjust scope` / `Stop` if scratch repo isolation is missing, ambiguous, or violated.
- **High: unsafe provider recommendation.** The conclusion must not recommend YOLO as safe or treat `local.autoReview` as an approval boundary. Block if YOLO is described without dangerous/unattended semantics or if `autoReview` is promoted to v1 Ask mode.
- **High: unsafe persistence design.** Guidance must not store API keys in `AgentPersistenceHandle.metadata`, result JSON, SDK stores, or `$PASEO_HOME` provider directories. Block if any design stores credential values.
- **Medium: over-implementation during spike.** This plan is docs/design only. Block if it modifies production provider registration, manifest metadata, or a production `cursor-sdk-agent.ts`.
- **Medium: misleading failure handling.** The proceed/adjust/stop recommendation must preserve blocked auth/config/runtime facts instead of converting them into silent fallbacks.

High severity threats block execution until the document is corrected.

</threat_model>
