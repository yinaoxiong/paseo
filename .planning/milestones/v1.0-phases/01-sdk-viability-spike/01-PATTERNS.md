## Patterns By File

### `packages/server/package.json`

**Role:** server workspace dependency boundary.  
**Closest analog:** existing direct SDK dependencies in the same `dependencies` object.  
**Pattern:** add `@cursor/sdk` as a real dependency of `@getpaseo/server` using npm in the
devcontainer. Keep dependency edits generated by the package manager rather than hand-editing the
lockfile.

```json
"dependencies": {
  "@agentclientprotocol/sdk": "^0.17.1",
  "@anthropic-ai/claude-agent-sdk": "^0.2.133",
  "@getpaseo/client": "0.1.96",
  "@getpaseo/highlight": "0.1.96",
  "@getpaseo/protocol": "0.1.96",
  "@getpaseo/relay": "0.1.96",
  "@isaacs/ttlcache": "^2.1.4",
  "@modelcontextprotocol/sdk": "^1.20.1",
  "@opencode-ai/sdk": "1.14.46"
}
```

**Implementation notes:**

- Use the server workspace as the dependency owner because the future provider runs in the daemon.
- Do not vendor SDK runtime files manually.
- If install/typecheck works but local runtime fails because native helpers or lifecycle scripts are
  missing, record that as spike evidence rather than hiding it with custom install behavior.

### `package-lock.json`

**Role:** generated npm lockfile.  
**Closest analog:** any current workspace dependency resolution in the root lockfile.  
**Pattern:** update only through npm install from the devcontainer. The lockfile should be reviewed
for unexpected workspace churn, but not manually shaped.

**Implementation notes:**

- Expected change: new `@cursor/sdk` package entry and transitive runtime packages.
- Risk to record: whether `npm ci --ignore-scripts` leaves the local SDK runtime usable.

- Keep live probes out of default test scripts; they depend on credentials and external service

### SDK Lifecycle Mapping

**Role:** prove Cursor SDK can satisfy Paseo's direct provider contract.  
**Closest analogs:** `AgentClient` / `AgentSession` interfaces, `runProviderTurn`, and Claude's
direct SDK-backed session.  
**Data flow:** prompt -> provider turn -> stream events -> terminal event -> `AgentRunResult`.

Direct provider contract:

```ts
export interface AgentSession {
  readonly provider: AgentProvider;
  readonly id: string | null;
  readonly capabilities: AgentCapabilityFlags;
  run(prompt: AgentPromptInput, options?: AgentRunOptions): Promise<AgentRunResult>;
  startTurn(prompt: AgentPromptInput, options?: AgentRunOptions): Promise<{ turnId: string }>;
  subscribe(callback: (event: AgentStreamEvent) => void): () => void;
  streamHistory(): AsyncGenerator<AgentStreamEvent>;
  describePersistence(): AgentPersistenceHandle | null;
  interrupt(): Promise<void>;
  close(): Promise<void>;
}

export interface AgentClient {
  readonly provider: AgentProvider;
  readonly capabilities: AgentCapabilityFlags;
  createSession(
    config: AgentSessionConfig,
    launchContext?: AgentLaunchContext,
    options?: AgentCreateSessionOptions,
  ): Promise<AgentSession>;
  resumeSession(
    handle: AgentPersistenceHandle,
    overrides?: Partial<AgentSessionConfig>,
    launchContext?: AgentLaunchContext,
  ): Promise<AgentSession>;
  listModels(options: ListModelsOptions): Promise<AgentModelDefinition[]>;
}
```

Provider runner terminal handling:

```ts
if (event.type === "turn_completed") {
  usage = event.usage;
  settled = true;
  resolveCompletion();
  return;
}
if (event.type === "turn_failed") {
  settled = true;
  rejectCompletion(new Error(event.error));
  return;
}
if (event.type === "turn_canceled") {
```

Claude direct provider `run()` pattern:

```ts
async run(prompt: AgentPromptInput, options?: AgentRunOptions): Promise<AgentRunResult> {
```

**Implementation notes:**

- Phase scripts should count SDK stream event types and capture stable fields, not build the final
  Paseo mapper.
- Treat tool args/results as `unknown` evidence; do not overfit to unstable payloads.
- Always dispose/close SDK agents in `finally`.

### Cancellation Probe

**Role:** prove `run.cancel()` behavior and terminal status.  
**Closest analog:** Claude maps interruption to `turn_canceled`; `runProviderTurn` treats canceled
turns as resolved, not failed.  
**Data flow:** long-running prompt -> run handle -> supports/cancel -> wait -> JSON evidence.

```ts
const requestCancel = () => {
  if (cancelIssued) {
    return;
  }
  cancelIssued = true;
  this.rejectAllPendingPermissions(new Error("Permission request aborted"));
  this.finishForegroundTurn({
    type: "turn_canceled",
    provider: "claude",
    reason: "Interrupted",
  });
  void this.interruptActiveTurn().catch((error) => {
    this.logger.warn({ err: error }, "Failed to interrupt during cancel");
  });
};
```

Terminal cleanup pattern:

```ts
private finishForegroundTurn(
  event: Extract<AgentStreamEvent, { type: "turn_completed" | "turn_failed" | "turn_canceled" }>,
): void {
  if (event.type === "turn_failed" || event.type === "turn_canceled") {
    this.flushPendingToolCalls();
  }
  this.notifySubscribers(event);
  this.activeForegroundTurnId = null;
  this.cancelCurrentTurn = null;
  this.activeTurnHasAssistantText = false;
  this.syncTurnState("foreground turn terminal");
}
```

**Implementation notes:**

- Check `run.supports("cancel")` and record `unsupportedReason("cancel")` before assuming support.
- Record whether `run.wait()` returns `"cancelled"`, `"finished"`, throws, or returns `"error"`.
- A cancellation limitation is a provider design finding, not a reason to add a fake interrupt path
  in Phase 1.

### Cross-Process Resume Probe

**Role:** prove the future provider can persist and resume Cursor SDK state.  
**Closest analog:** `AgentPersistenceHandle` and Claude `resumeSession`/`describePersistence`.  
**Data flow:** process A writes handle -> process B reads handle -> same store/cwd/model/mode ->
`Agent.resume` -> continuity prompt result.

Persistence handle contract:

```ts
export interface AgentPersistenceHandle {
  provider: AgentProvider;
  sessionId: string;
  /** Provider specific handle (Codex thread id, Claude resume token, etc). */
  nativeHandle?: string;
  metadata?: AgentMetadata;
}
```

Claude resume pattern:

```ts
async resumeSession(
  handle: AgentPersistenceHandle,
  overrides?: Partial<AgentSessionConfig>,
  launchContext?: AgentLaunchContext,
): Promise<AgentSession> {
  const metadata = coerceSessionMetadata(handle.metadata);
  const merged: Partial<AgentSessionConfig> = { ...metadata, ...overrides };
  if (!merged.cwd) {
    throw new Error("Claude resume requires the original working directory in metadata");
  }
  const mergedConfig: AgentSessionConfig = {
    ...merged,
    provider: "claude",
    cwd: merged.cwd,
  };
  const claudeConfig = this.assertConfig(mergedConfig);
  return new ClaudeAgentSession(claudeConfig, {
    defaults: this.defaults,
    runtimeSettings: this.runtimeSettings,
    handle,
    agentId: launchContext?.agentId,
    launchEnv: launchContext?.env,
    logger: this.logger,
    queryFactory: this.queryFactory,
    resolveBinary: this.resolveBinary,
  });
}
```

Claude persistence pattern:

```ts
describePersistence(): AgentPersistenceHandle | null {
  if (this.persistence) {
    return this.persistence;
  }
  if (!this.claudeSessionId) {
    return null;
  }
  this.persistence = {
    provider: "claude",
    sessionId: this.claudeSessionId,
    nativeHandle: this.claudeSessionId,
    metadata: { ...this.config },
  };
  return this.persistence;
}
```

**Implementation notes:**

- For Cursor SDK, `nativeHandle` should be the SDK `agentId`.
- Metadata should include `runtime`, `cwd`, `storePath`, `model`, `modeId`, and
  `sandboxEnabled`.
- Resume success must be conversation-based: process B should ask a follow-up whose answer depends
  on process A's prompt/response, not just prove `Agent.resume()` returned an object.
