# Requirements: Paseo Native Cursor SDK Provider

**Defined:** 2026-06-13
**Core Value:** Paseo can launch, monitor, resume, and control Cursor SDK agents as a first-class provider with clear local execution safety semantics.

## v1 Requirements

### SDK Viability

- [x] **SDK-01**: A targeted spike confirms `@cursor/sdk` can be installed and imported in the server workspace without breaking existing package boundaries.
- [x] **SDK-02**: The spike validates local `Agent.create`, `agent.send`, streaming, `run.wait`, cancellation, and `Agent.resume` behavior in a Paseo-compatible Node environment.
- [x] **SDK-03**: SDK error surfaces are documented separately for startup/config/auth failures and in-run failures.

### Provider Lifecycle

- [x] **PROV-01**: Paseo has an experimental direct provider with id `cursor-sdk`.
- [x] **PROV-02**: The provider implements `AgentClient` and `AgentSession` without depending on ACP process transport.
- [x] **PROV-03**: The provider emits canonical user timeline items for submitted prompts and maps SDK assistant/tool/reasoning events into Paseo stream events.
- [x] **PROV-04**: The provider persists a resume handle that can recreate a Cursor SDK agent after daemon restart.
- [x] **PROV-05**: The provider supports interruption/cancellation using the SDK's run lifecycle where available.

### Modes and Safety

- [x] **MODE-01**: The provider exposes a Sandbox mode that runs Cursor SDK local agents with sandboxing enabled.
- [x] **MODE-02**: The provider exposes a YOLO mode that runs Cursor SDK local agents without sandboxing and is marked unattended/dangerous in Paseo metadata.
- [x] **MODE-03**: The provider does not expose a generic Agent mode in v1.
- [x] **MODE-04**: Missing SDK support for interactive approval is documented and not represented as an Ask mode.

### Models and Features

- [x] **FEAT-01**: The provider lists available Cursor models through the SDK when stable model discovery is available.
- [x] **FEAT-02**: The provider maps Cursor thinking or reasoning options into existing Paseo feature/model controls only when the SDK metadata is stable enough to avoid misleading users.
- [x] **FEAT-03**: Provider snapshots avoid creating empty Cursor SDK sessions just to discover metadata.

### Product Integration

- [x] **UI-01**: The provider appears in built-in provider metadata with clear experimental copy and mode visuals.
- [x] **UI-02**: The app can render the provider icon/name/modes using existing provider selection and composer controls.
- [x] **UI-03**: Existing Cursor ACP provider/catalog behavior remains unchanged.

### Quality and Documentation

- [x] **QUAL-01**: Targeted tests cover provider registration, mode metadata, lifecycle event mapping, and resume handle behavior.
- [x] **QUAL-02**: Provider docs explain SDK auth, Sandbox vs YOLO semantics, and why Ask/Agent are not v1 modes.
- [x] **QUAL-03**: `npm run typecheck` and `npm run lint` pass after implementation changes.

## v2 Requirements

### Future Expansion

- **FUT-01**: Evaluate Cursor SDK cloud runtime after local provider lifecycle is stable.
- **FUT-02**: Evaluate SDK custom tools and MCP server wiring after base provider event mapping is proven.
- **FUT-03**: Revisit interactive approval if Cursor SDK exposes a stable host approval API.
- **FUT-04**: Consider replacing or merging Cursor ACP only after SDK auth and feature coverage are better than ACP for normal users.

## Out of Scope

| Feature                            | Reason                                                                                                    |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Interactive Ask mode               | SDK currently lacks a stable host approval response API comparable to Claude provider permission handling |
| Paseo-managed Cursor API key store | Adds credential scope before the SDK provider is proven                                                   |
| Cursor SDK cloud runtime           | Local runtime is the product-critical path for Paseo's dev-environment control model                      |
| Cursor ACP replacement             | Existing ACP remains useful for CLI-login users and must not regress                                      |
